# iOS source port

- Follow the repository's binary-only terminal-core policy. Consume the public header from the verified XCFramework module; never copy standalone core headers, Rust, JNI or CMake sources or core build logic into the application.
- The device arm64 and simulator arm64/x86_64 XCFramework is integrated through the Xcode Frameworks phase. Its independent root `terminal-core.ios.lock.json` pins clean core `f51936441dea83fa2f9459386fb6c35b90102979`, schema 2 and Rust 1.97.1. Keep the original Windows/Android `terminal-core.lock.json` and five libraries at their own revision and bytes; do not combine provenance or fall back to that lock.
- Every Debug and Release build must run `scripts/verify_native.swift` with the macOS SDK before linking. Reject missing or modified artifacts and metadata rather than bypassing verification or injecting alternate framework/header search paths.
- On 2026-10-25, the integrated project passed all 48 tests on each of the iPhone 18 Pro and iPad Pro 13-inch (M5) / iOS 27.0 arm64 simulators with no failures or skips, all 16 artifact-verifier tampering tests, and an unsigned device arm64 Release build without framework/header path or link overrides. Nothing was installed or released to a physical device. See PARITY.md and `../docs/development/IOS_NATIVE_CORE.md` for precise validation and import scope. Real Relay/host/device acceptance remains pending; native unit tests do not establish Android feature parity or a working remote terminal end to end.
- The shared scheme also runs TermLinkUITests. After the iOS Server/AI follow-up, the final simulator run passed 73 tests on each device (70 logic/native + 3 UI), with no failures or skips. Run UI smoke on dedicated unsigned-in simulators; its process-only server argument prevents real-account auto-connect. Simulator UI checks cover navigation, licenses, and local shortcuts, not remote CLI/AI acceptance.
- Server iOS configuration and schema 51 wiring are documented in `../server/IOS_ACCESS.md`. Keep IOS identity distinct while reusing the legacy mobile wire role and exact `termlink.file-transfer.v2` subprotocol. A send receipt may clear only its own attachment/reference payload; preserve content prepared while awaiting the response.
- The subsequent attachment/directory work passed 91 tests on each iPhone/iPad simulator (88 logic/native + 3 UI) and the unsigned device Release build. See ATTACHMENTS.md: encrypted upload caches and metadata are account-scoped; recovered records require explicit retry, the original host/session/PC/control version, the same attachment ID and digest, and an authoritative host offset. Never auto-send recovered content or rebind it to a different computer. Directory-to-AI creation must preserve the selected PC and directory, with no fallback to another online PC.
- Frozen history is presentation-only: live native state still applies and persists before ACK. Keep input and host resize disabled while browsing; release native captures before expiry and recheck lease validity on return. Shell command navigation must re-read the command ID and prompt anchor, reject alternate/non-primary pages, and never reuse an anchor across a terminal reset.
- Keep AI presentation in the shared, bundled `android/app/src/main/assets/ai-web` resources. Remote third-party pages must never receive the TermLink native bridge or application tokens.
- Agent additions must update `AgentBrand`, aliases, bundled image sets, source/license notices, `sync_agent_assets.py` and the bundle asset test in the same change. Unknown agents keep the generic fallback.
- Retain phone tabs and iPad sidebar/detail behavior. Do not integrate the deferred free-window tablet design without a new request.
- Signatures, provisioning profiles, tokens and `Local.xcconfig` stay out of Git. Core Release builds must pass the artifact lock check; missing capability must disable that feature explicitly.
