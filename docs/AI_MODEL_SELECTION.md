# AI 模型选择

AI 新建对话中的模型列表由 Windows Agent 在本机协议上读取，再通过已有的加密 AI 桥接发送到 Android。Android 不保存模型密钥，也不写死供应商列表。

- Codex：完成 `initialize` 后调用只读 `model/list`，按 `nextCursor` 分页，最多保留 200 个非隐藏模型。创建对话仍使用返回的 `model` 值。
- Claude：只执行初始化控制请求，使用返回的 `models[].value` 和 `displayName`。不会发送用户提示词或创建会话。
- ZCode 原生：当前桌面协议没有稳定的模型列表 RPC，因此显示手动输入。Provider ID 与模型 ID 必须同时填写；ZCode 桌面远控由其官方页面负责模型选择。

列表请求有 20 秒超时、8 页/200 项上限、重复 ID 和循环游标保护，并限制同一 Windows Agent 同时进行的查询数。查询失败不会阻止“使用电脑默认模型”或手动输入。设备、Agent 或 Windows host incarnation 变化后，旧回复会被丢弃。

模型发现协议测试覆盖分页、隐藏项、重复项、非法数据、游标循环、取消清理、权限/主机隔离，以及不创建对话、不发送 turn 的约束。

## 独立模型与推理强度菜单（2026-10-04）

新建 AI 对话和已有会话使用同一个控件，模型与推理强度分别打开下拉菜单。已有会话保持「附件、授权在左，模型、强度、发送在右」的紧凑单行布局；新建页面也将两个入口并排显示。

- 两个菜单共用 Windows 返回的模型能力；先打开强度菜单也会查询，无需先打开模型菜单。电脑、Agent 或 host incarnation 变化后清除旧列表。
- 新建时切换模型保留仍受支持的强度，不兼容或手动输入未知模型时重置为默认；未知模型不沿用上一个模型的档位。已有会话继续由 Windows 校验并应用模型和强度配置。
- 明确不支持推理强度的模型隐藏强度入口；能力未知时允许打开查询并显示原因，不编造固定档位。
- Claude 等仅允许新建时设置强度的 Agent，在已有会话中允许查看选项，并显示「仅对新建会话生效」，选项不可修改。生成或未确认操作期间也不能提交配置更改。

验证：32 项 Android AI 单元测试通过；`emulator-5556` 的真实 ProductActivity 与 HOME-PC 联合验证两个独立菜单、新建 Codex 的模型/强度回执、已有会话分别切换模型/强度、兼容强度保留、手动未知模型清空旧档位，以及 Claude 新建/已有会话的强度限制。本轮未发送生成任务。明确 unsupported 的隐藏分支由单元测试覆盖。
