## 紧凑设计

- 新按钮的视觉高度以 28–34 dp 为目标，用图标配短文字；有效触控区至少 48 dp。压缩装饰、内边距和重复信息，不靠缩小正文换空间。
- AI 列表改为紧凑行：标题与状态一行、Agent/电脑/目录一行、摘要一行；去掉大卡片页脚和重复“新建”入口。
- AI 详情将标题、Agent、电脑和目录收在同一个 52 dp 左右的头部，删除独立目录栏；有未决任务时才显示简短状态条。
- 消息输入栏单行起步，内容增加时向上增长，达到上限后内部滚动。键盘由原生输入框触发，AI 不额外复制终端键盘按钮或 Dock。
- 审批卡片保留命令/操作与明确的批准范围，更多详情折叠。“拒绝 / 允许本次”使用紧凑按钮，不占整行宽度。
- 创建页的模型与权限可在正常字号和足够宽度下并排；窄屏或大字号切回纵向布局，完整标签不截断。
- 新功能正文以可读字号为先，支持用户字体设置和系统字体缩放。紧凑规则不应用到 CLI 原页面。

固定画框下，浏览器自检测得 AI 消息区高度为 558 CSS px（画框高 806 px）；这是原型布局数据，不是 Android 实机测量。

## 页面与行为

1. 底部调整为“设备 / CLI / AI / 设置”。原“会话”仅更改显示名称为 CLI，继续复用原页面、页签和功能。AI 新增独立列表与详情。设备页显示电脑的全部会话，CLI / AI 各自仅显示手机打开的会话。
2. 设备卡片提供“新建会话”，底部选择面板分为“AI 对话”和“CLI 终端”。AI 栏目的“新建”只创建结构化对话，可选择执行电脑。Agent 列表来自当前电脑的能力目录。
3. 创建 AI 会话只显示工作目录、Agent 支持的模型/权限模式、可选首条消息。电脑本地认证和程序路径不放进手机表单。
4. Codex、Claude Code、Grok Build 共用 AI 对话布局；功能由实际协商能力决定。示例图标仅为文字标识，不是官方品牌资源。
5. 普通消息输入使用 Android 输入法；单指滑动浏览聊天。AI 页面不沿用终端鼠标滚轮或终端按键 Dock。普通终端继续保留现有体验。
6. 工具详情默认折叠；需要审批时显示命令/文件、工作目录和明确作用范围。“允许本次”与“拒绝”在卡片内完成。
7. 需要用户回答时，问题卡片提供选项与自由补充，暂时收起普通消息输入框，避免两套输入和提交按钮产生歧义。
8. CLI 云朵菜单完整复用：控制权、触摸鼠标、滚轮位置、尺寸调整和网络检测都保留。新增 AI 菜单按“控制权限 / 连接 / 当前会话”组织。两者的网络选项均遵守服务端策略；只代理策略隐藏 LAN/NAT 测试。
9. CLI 关闭页签与 AI 关闭对话视图都只退出手机视图，不终止电脑进程；结束会话单独确认并等待 Windows 回执。AI 关闭视图后从本机 AI 列表移除，仍可从设备页重新打开。
10. 电脑确认离线后隐藏会话内容、显示状态待确认，保留手机未发送草稿。手机暂时断网与电脑确认离线应分别显示，不能从一次请求超时推断电脑离线。
11. 在终端里运行 Codex / Claude / Grok 仍属于 CLI；结构化协议创建的会话进入 AI。不能通过终端标题或进程名称自动转换会话类型。
12. 点击底部栏目时保留 CLI 当前页签和原终端状态，保留 AI 当前页面、草稿及阅读位置。AI 详情返回列表切换对话，不在 AI 标题栏混入 CLI 页签。

## 正式实现需覆盖的状态

| 场景 | 反馈与处理 |
|---|---|
| 初次加载能力 | 有限时加载；失败显示重试，不覆盖已知目录为“未安装” |
| 手动重新检测 | 显示单次进度，重复点击合并，完成后更新目录 |
| Agent 缺失、禁用、不兼容 | 给出原因；已安装但不兼容时可按能力保留终端入口 |
| Agent 认证未知 | 显示“尚未验证”；不能与“需要登录”混用 |
| 创建中 | 防重复提交；失败保留表单，按原请求 ID 查询结果 |
| 正在生成 | 状态条显示生成状态；支持时显示中断；普通发送/排队按 Agent 能力开放 |
| 只读 | 允许浏览，禁用发送和审批，显示获取控制权限 |
| 审批/回答提交中 | 禁止重复操作，等待电脑确认后更新卡片 |
| 请求被电脑处理或已过期 | 撤销按钮，显示已处理/已失效，不伪造用户决定 |
| 本机输入法展开 | 输入区域位于输入法上方，隐藏底部主导航；保留阅读位置与草稿 |
| 手动浏览历史 | 新消息不强制拉到底部，显示“回到最新” |
| 网络切换/重连 | 保留发送状态，按请求 ID 与事件序号恢复；不重复执行 |
| 会话结束 | 清除未决操作，显示 Windows 确认的结束状态 |

原型中的网络检测、创建和审批结果为演示，不代表当前设备安装或实际网络能力。正式代码必须等待 Windows 的权威回执。附件、模型目录、只读模式、恢复和中断等控件仅在相应 Agent 支持时出现。

## 布局约束与验证

- 使用当前 Android 产品的深色背景、蓝色主色、绿色成功和黄色等待提示。
- 正式 Compose 实现使用 dp/sp，主要控件触控区域至少 48 dp；紧凑视觉不缩小有效点击范围。
- 适配窄屏、横屏、系统字体放大、屏幕阅读器及输入法；设计稿的固定手机画框仅用于展示。
- 静态图经过 Chrome 浏览器渲染和目视检查。
- 打开 `android-ai-agent-prototype.html?selftest=1` 可运行原型自检，页面底部输出 `SELFTEST PASS` 或失败原因。
- 自检覆盖四栏导航、CLI 原图引用、AI 草稿保留、设置入口、Agent 选择、创建、审批消费、只读、控制权恢复、代理策略菜单、离线隐藏内容、问题提交及紧凑布局；不等同于 Android/Windows 联调测试，也不测试截图内的 CLI 功能。
