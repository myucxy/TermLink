## 诊断结论（2026-09-17 补齐，已修复）

**假设 1 成立（次要因素）、假设 2 排除、假设 4 是主因，且发现关键拓扑**：

1. **主因 · server 广告的 issuer 模拟器无法解析**。容器以 `TERMLINK_PUBLIC_URL=https://termlink.local` 启动，`/v1/client-config` 返回 `oidc_issuer=https://termlink.local/realms/termlink`；app 的原生 OIDC 客户端随后必须从该 origin 拉取 discovery（`NativeOidcAuth.kt` 的 `OidcEndpointPolicy` 强制 issuer/端点 HTTPS 且同源，`NativeOidcAuth.kt:139/169/174`），而模拟器内 `termlink.local` DNS 解析失败（实测 `ping: unknown host`）→ 登录在 discovery 一步即死。
2. **关键拓扑（此前未知）**：Android 内置默认服务器地址就是 `https://termlink.kget.cc:8910`（`android/app/build.gradle.kts:17`）。该域名在局域网 DNS 解析到 **192.168.9.250**——一台 TLS 网关（Let's Encrypt `*.kget.cc` 通配符证书）监听 8910，反向代理到本机 Docker 的 192.168.9.28:8080。即正确部署形态是：**app → kget:8910（HTTPS 终结）→ 本地 Docker server（纯 HTTP）**，server 广告的 issuer 必须是 kget origin。
3. **假设 1（端口绑定）属实但为次要**：`127.0.0.1:8080` 连接拒绝（绑定仅在 192.168.9.28），模拟器走 `10.0.2.2` 不通；走 `192.168.9.28:8080` 通（实测 nc rc=0）。
4. **假设 2（000048 关注册）排除**：本地库 `registration_policies.mode = OPEN`（version 3，管理员已改）。
5. **假设 3（WIP auth 改动）无需追查**：请求根本没走到认证层。
