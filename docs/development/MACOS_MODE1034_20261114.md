## 确定首错与核心策略

此前受测 Mac `/bin/sh` 在 `TERM=xterm-256color` 下输出 `ESC[?1034h`，
core ef177a8 返回 Unsupported 并将会话停止于 INTERRUPTED。这解释了该轮手机
“快照成功但不能保持输入”的实际阻塞；不能据此补认此前所有恢复偶发失败都同源。

模式1034是 xterm eightBitInput。TermLink 现有输入采用 UTF-8 与 ESC-prefixed Alt/Meta，
本次明确保持这一固定策略：只识别1034的set/reset，DECRQM准确报告4（permanently reset），
不实现可切换的八位Meta模式，不新增状态/快照字段，不改C ABI/JNI，也不在客户端丢协议字节。
未知9999等仍failed-closed。core说明见独立仓库 `docs/META_INPUT_1034_FIX.md`。

编译来源固定为 clean core `0d5b8d9fbdfc9c6cbb21588b729eefa916d9d221`。
它是本机独立检出的构建提交，保留在共享core的本地分支 `fix/macos-mode1034-20261114`，
未推远端、未切换共享HEAD、未清理既有修改。五库、Mac、iOS三份独立消费者锁均真实更新到该revision。
完整对应源码及构建资料须在对外分发前按发布手册提供；本地ref/私有仓库不替代分发义务。

## iOS诊断

新增受限TL-DIAG V1/V2解析、明确V3未知说明、本地详情与显式复制。
只接受真实Relay解密后确认recipient字段等于当前设备的sealed SessionEnded证据；
wrong recipient、篡改、broadcast、重复/非法字段、原始控制符均拒绝。
畸形诊断仍结束生命周期/停止输入，不合成Shell退出码；提交或ACK失败保留最后画面。
诊断不进入通用error文本或服务器遥测。
