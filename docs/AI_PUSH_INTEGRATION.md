# AI 通知与推送接入

更新：2026-10-04。用户确认目前没有小米推送、Firebase 项目，先完成通用代码与接入说明。本文件不代表推送通道已经开通。

## 当前可用边界

- AI 消息、历史、文件、待审批事项以 Windows 为权威。通知不携带提示词、工具命令、聊天正文或登录凭据。
- `AiNotifications.kt` 实现系统通知、会话跳转、允许本次／拒绝入口。Android 13 及以上请求通知权限；Android 12 及以上敏感操作要求解锁。复杂问答进入会话表单。
- Intent 只包含随机本地票据。票据内容使用现有 Android Keystore 加密，绑定账号、电脑、会话、Windows 实例、控制版本及待审批 ID；普通跳转 24 小时、审批入口 10 分钟失效，Windows 自己的截止时间仍然生效。
- 点击后直接重读 Windows catalog 和会话，绕开正在等待的 watch；主机重启、控制权改变、已处理审批均不执行旧动作。执行走原 `answer` 操作和持久化 operationId，收到成功回执才关闭提醒；未知结果进入原重试流程，不自动新建一次审批。
- 当前通知操作通过 Activity 处理，可从已展示的通知冷启动进入会话。**尚无 FCM MessagingService、小米 Receiver、推送 Token 登记、Server 推送网关或无界面的 Worker。**
- 现有后台检测是进程和认证连接仍可执行时的尽力轮询。模拟器 Android 16 实测应用进入 cached/frozen 后轮询停止；不能承诺锁屏、杀进程、强制停止后仍实时提醒。不用无关类型的前台服务或悬浮窗绕开限制。

## 目标设备与通道

| 环境 | 首选通道 | 当前无账号时的行为 |
| --- | --- | --- |
| 小米／Redmi、MIUI／HyperOS，无 Google 服务 | 小米系统推送 | 仅在线且进程可执行时检测，冻结后等恢复前台同步 |
| 小米且有 Google 服务 | 小米优先，FCM 为可选注册；事件 ID 去重 | 同上；不能两个通道重复弹出同一审批 |
| 其他品牌且 Google 服务可用、网络可达 | FCM | 同上 |
| 其他品牌、无 Google 服务 | 后续按实际机型接相应厂商通道 | 不能把小米 SDK 或装入 Firebase 等同于通用离线可达 |

各通道都使用标准系统通知。小米胶囊／灵动岛属于另外的厂商能力与准入，不影响通知、跳转和审批的基础验收；当前没有声明支持胶囊。

## 申请小米推送需要准备什么

1. 在小米开放平台 `https://dev.mi.com/` 完成账号及主体认证，创建 Android 应用、开通消息推送服务；按控制台当时要求填写应用资料、隐私政策、签名和应用类别。
2. 登记实际正式 applicationId。当前正式包为 `dev.termlink.harness`；DEV/验证包使用独立后缀，必须独立登记和隔离 Token，不可混用正式应用记录。
3. 保存控制台发放的 AppID、AppKey、AppSecret，并记录项目、地域、服务端接口版本和使用限制。AppSecret 只放受保护的 Server 凭据存储；不放 Android assets、Web JS、日志或 Git。
4. 从小米官方渠道选择明确版本的 SDK，核对许可证、隐私合规资料、包 SHA-256 或签名并记录后接入。当前未选择或下载 SDK，不提供猜测的版本号、密钥或接口实现。
5. 提供一台目标小米真机的型号、系统版本和有／无 GMS 情况；在手机设置中授予通知权限。自启动和电池设置只按真机实际需要引导，不能把设置完成写成送达保证。

## 申请 Firebase 需要准备什么

1. 在 `https://console.firebase.google.com/` 创建项目，添加与实际 applicationId 一致的 Android 应用；DEV 与正式环境隔离。
2. 下载对应应用的 `google-services.json`，保存到受保护的构建配置目录。当前仓库没有开启 Google Services 插件或 Firebase Messaging 依赖，单独放入文件不会自动启用推送。
3. Server 使用 FCM HTTP v1 的服务身份。优先使用部署平台工作负载身份；必须用服务账号 JSON 时，将私钥作为 secret 挂载，只授予发送消息所需权限。服务账号 JSON 不能放进 APK 或仓库。区分 Android 项目配置与服务端私钥。
4. 若控制台要求签名指纹，从本次正式签名 APK/连续性证书读取 SHA-256、SHA-1；不要拿 debug 证书代替正式证书。使用已有 Android SDK 的 `apksigner verify --verbose --print-certs <APK>`，并按发布手册核对指纹。
5. 记录 Project ID、Project Number/Sender ID、Android Firebase App ID 和配置文件位置。后续告知配置文件路径或受保护凭据名称即可，不在聊天中发送密钥。

## 接入时必须补充的代码

按照 `AI_WEB_IMPLEMENTATION_PLAN_20261004.md` 的推送阶段独立实施，不能只接 SDK 就宣称完成：

1. **Windows 事件来源**：从真实会话变化生成 completed/failed/approval_required/input_required/resolved 事件；绑定收件设备、eventId、会话、主机实例、过期时间。仅面向仍授权且已订阅的设备。
2. **冷启动安全信封**：使用可信设备密钥与现有密码能力设计可在重连前校验的信封，包含接收设备、协议版本、nonce、截止时间和重放防护。不能把已结束实时连接的会话密钥状态硬套给冷启动；这一步需要协议与安全复核。
3. **Server**：新增登录和设备绑定的 Token 注册／轮换／注销、撤销信任清理、发送权限、频率和队列限额、过期丢弃、提供商无效 Token 清理。保存最少路由元数据及加密载荷，不保存明文会话内容。凭据只由网关读取。
4. **Android**：接入官方 FCM `onNewToken/onMessageReceived` 与小米注册／接收回调。将校验后的事件按 eventId 持久去重，再复用通用通知入口；后台动作复用相同 Windows 请求服务与 operationId，而不是操作 WebView DOM。
5. **投递与业务状态分开**：提供商接受、设备收到、通知显示、用户点击、Windows 执行是五个不同回执。失联时显示待确认，不能把 HTTP 200 当作任务批准。
6. **注销和多账号**：停止旧账号订阅、取消旧提醒、撤销 Token 绑定、清理票据；冷启动未登录只提示重新登录，不能自动把旧审批转到新账号。

当前不创建空的多厂商插件框架；先以小米及 FCM 两条真实通道完成闭环，再按实际无 GMS 机型扩展。

## 验收清单

- 标准通知权限允许／拒绝、普通完成提醒、点击定位电脑与会话、复杂问题进入表单。
- 允许／拒绝分别验证 Windows 收到真实决定；重复点击、双端竞争、超时、主机重启、换账号、撤销信任不能执行陈旧动作。
- 网络断开或回执丢失保持未知操作，重连沿用同一 operationId；不冒充成功。
- 真机前台、后台、锁屏、进程被回收、重启、Token 更新、GMS 不可达、无 GMS、小米省电策略分别记录；用户强制停止应用后的系统限制单独说明。
- 不同推送通道对同一 eventId 不重复弹窗；审批已在电脑处理后旧通知正确失效。
- Android 模拟器可验 UI 和本地票据，不可代替小米系统推送及真机投递验收。
