# Windows 鼠标桥接修复与 Android 手势评估

2026-09-25；基于 `9372f7e` 后的修改。双端发布状态见 `RELEASE_0.2.66_122.md`。

## 根因与修改

用户确认普通 PowerShell/CMD 可以滚动，只有 Codex 等交互程序不能滚动。
交互程序启用鼠标报告后，Windows Terminal 把滚轮交给程序，外层 ConPTY 将其转换为
Win32 `MOUSE_EVENT_RECORD`。SessionHost 原先只处理 `KEY_EVENT`，因此鼠标事件在这里丢失。
这与 Android 的触摸开关是两条输入路径，关闭手机开关不能修复 Windows 本地窗口。

旧安装版的隔离对照：同样发送 8 次滚轮与 4 次键盘输入，直接启动的子程序收到 8/4，
经过 SessionHost 只收到 0/4。两个测试都使用随安装包分发的 ConPTY，正常退出。
证据：`artifacts/validation/mouse-scroll-probe.json` 及同名前缀的输出、控制台模式记录。

本次修改：

- 在公共 SessionHost 输入桥中补齐滚轮、按下、释放、拖动和悬停，两个启动路径均处理。
- Win32 缓冲区坐标转换为视口格坐标；映射左右中键、修饰键、水平/垂直滚轮，累积不足一格的滚轮增量。
- Agent 托管会话复用 native terminal-core 协商的鼠标编码；独立 Host 使用 ConPTY SGR 格坐标传输。
- 保持键盘与鼠标到达顺序，包括等待终端应答分类的 Escape；使用可直接映射的 Win32 结构布局，防止新增联合字段破坏键盘记录。
- 点击、滚轮与拖动沿用本地输入优先权；纯悬停不抢走手机控制权。未启用鼠标报告时，托管路径不写入鼠标数据。
- 不开启无条件鼠标捕获，保留终端前端的普通选择、复制和历史滚动处理方式。
- 缩放导致的过期坐标、旧编码坐标上限、无法提供像素的 1016 模式不终止会话；不伪造像素坐标。

Windows 改动集中在 SessionHost；Android 手势改动见下文。native Rust core、Server 与网络协议未改动。
发布时更新 Windows 安装包中的 SessionHost；本轮无需为此重编 Server 镜像。

## Android 0.2.65 评估

现有默认方案合理，但触摸开关开启后的行为并非完整的手机交互方案。

| 状态 | 当前实际行为 | 评估 |
| --- | --- | --- |
| 默认关闭 | 点击打开键盘，单指浏览终端历史，长按选择 | 保留，避免程序启用鼠标后抢走手机常用操作 |
| 开启 | 单指按下/移动/抬起发送鼠标按下/拖动/释放 | 支持点击和拖拽，但不能模拟滚轮，无法靠滑动翻程序内部内容 |
| 开启后加第二根手指 | 释放当前按键并消费剩余手势 | 没有双指滚轮，不能把它当成已有功能 |
| 程序关闭鼠标报告或失去控制权 | 手指回到本地操作；菜单禁用 | 已保存的 ON 偏好无法关闭，程序重新启用报告时会再次生效，需优化 |

必须区分两种历史：终端保存的输出行可以本地浏览；Codex 等程序内部维护、尚未绘制的内容，
需要发滚轮/按键让程序翻页。单指本地历史不能代替后者，也不能恢复被全屏重绘覆盖的全部内部内容。

0.2.66 按本评估保留现有开关与独立键盘按钮，只调整开启后的手势：

1. 轻点在抬起确认后发送单击，单指滑动发送远端滚轮，长按后拖动才发送鼠标拖拽。
   延后按下可以避免想滚动时先误点程序；不要在同一手势中先发按下、再猜测是滚动。
2. 保留关闭开关后查看本地历史的方式；已开启的偏好应始终允许关闭，即使只读或程序当前不接受鼠标。
3. 整段手势仍固定用途；取消、控制权变化和多指打断必须结束捕获。程序是否接收输入仍由 core 和控制租约判断。

双指滚轮可以作为后续辅助操作，但发现成本较高，且必须处理第一根手指已按下的问题，
不宜只增加一个双指分支就认为交互完整。

0.2.66 的新手势仅在 **core 鼠标报告开启 + 用户触摸鼠标开关开启 + 当前有控制权** 时接管手指。
任何条件不满足时，新手势不接管：普通点击唤起输入法、滑动浏览本地内容、长按选择均沿用原路径。
鼠标报告状态来自 native core，不通过程序名或输出文字猜测；模式在手势中变化时消费剩余手势，
下一次按下才重新选择路径，避免孤立抬起触发误点击。真实物理鼠标保留直接 press/move/release。
滑动沿主方向锁定轴、累积不足一格的位移，不发送惯性滚轮；单个合并 MOVE 最多发送 32 次，避免积压。

## Android 辅助滚轮与紧凑菜单（0.2.67/123）

2026-09-25 的 Android 改动复用现有 core 鼠标编码、输入队列、E2EE 与控制租约；Windows/Server 无需改动。

- 仅当 core 开启鼠标报告、触摸鼠标偏好关闭、会话在线且手机持有控制权、未显示独立历史页时，
  在终端右侧覆盖半透明滚轮。覆盖层不参与终端尺寸测量，普通终端手势沿用原路径。
- 上下按钮每次发送一个滚轮刻度，中间手柄上下拖动连续发送；8 dp 死区暂停，距离增加后从
  4 加速到最多 20 刻度/秒。只有一个待执行回调，不补发延迟帧；松手、取消、多指、失焦、后台、
  控件移除或输入拒绝均停止，重获控制/焦点后不会自动继续。
- 坐标使用最近一次终端单指触摸的位置，没有触摸记录时使用可见终端中心；沿用 View 的格/像素坐标
  转换并裁剪到当前视口，不能使用悬浮按钮的位置冒充远端命中位置。不会为定位发送点击。
- Dock 首位固定为键盘开关，实际 IME 可见性决定开关状态，包含浮动输入法和系统返回键关闭。
  一行/两行高度仍为 34/67 dp；移除折叠状态。只读时允许关闭已显示的键盘。
- 云朵菜单保留单行状态标题；鼠标说明通过问号查看，窗口预览仅显示列×行，取消重复键盘菜单项。
  网络菜单继续遵循服务端策略，Relay-only 不显示 LAN/NAT 检测项。

这里只参考行为，未复制代码或资源、未接入 Termux 模块。新增控件使用 Android 原生 View。
