## 发布前优先处理

### A01 · P1 · 取回待发消息可能丢失文本

位置：`android/app/src/main/kotlin/dev/termlink/product/AiWorkspace.kt:293`；入口 `AiComposerOptions.kt:133`。

条件：队列已有消息 A，输入框又写了草稿 B，点击 A 的“取回”。当前逻辑先从队列删除 A，仅在草稿为空时才写入 A。B 非空时，A 从用户可访问的队列/草稿中消失。

建议：只有取回成功才删除队列项。已有草稿时可将取回内容追加到草稿，或让用户选择保留/替换；超出长度上限必须保留原队列项。用一个共用草稿写入入口处理，不在每个按钮中重复保护。

验收：空草稿、非空草稿、长度上限、失败/恢复队列四种情况，原文均可找回。

### A02 · P1 · 编辑旧消息直接覆盖当前草稿

位置：`android/app/src/main/kotlin/dev/termlink/product/AiWebConversation.kt:166`。

条件：已经输入新草稿，点击历史用户消息的“编辑”。当前直接赋值 `drafts[id] = text.take(16000)`，没有保留现有草稿，也会无提示截断较长文本。按钮实际行为是“填入输入框供再次发送”，并非修改原历史消息。

建议：与 A01 共用草稿保护；明确“编辑后重新发送”的含义。已有草稿时提供撤销或替换选择，超长文本显示限制，不静默截断。

验收：编辑旧消息、返回、切会话、旋转/重建后，两段文本都有明确归属；未经发送不改变历史。

### A03 · P1 · 服务器保存失败也按成功更新登录页

位置：`ProductActivity.kt:1288`、`:1374`、`:2091`；实际配置校验 `ProductionProductRepository.kt:1272`。

`runOperation` 无论成功失败，都会在 finally 调用 `onComplete`；登录页的配置完成回调却无条件更新显示地址并关闭弹窗。输入非法地址时，实际配置仍旧，显示地址可能变成新值，用户随后登录的目标与界面认知不一致。

建议：区分成功回调与“结束忙碌状态”。仅成功后关闭弹窗，显示值以 Repository 接受的规范地址为准；失败保留编辑内容，给字段级原因。

验收：无效格式、禁止的协议、正常地址均分别验证实际配置、显示地址和弹窗状态。

### A04 · P1 · 一个未知结果阻塞整个 AI 工作区

位置：`AiWorkspace.kt:206`、`:548`、`:590`、`:604`；输入限制 `AiComposerOptions.kt:113`。

当前 `busy`、`uncertain` 和持久化 `pending` 是整个工作区共用的。某台电脑的一次操作未收到回执后，其他电脑/会话的刷新和变更也会提前返回，界面广泛禁用，用户可能误以为所有电脑都不可用。

建议：先显示“哪台电脑、哪个会话、哪项操作待确认”，保留原 operationId 的查询入口。逐步把未知结果和写入限制限定到相关电脑/会话；独立电脑的只读目录/状态读取继续可用。不能通过清除 pending 或生成新请求绕过未知结果。

验收：电脑 A 丢回执时，电脑 B 可浏览和操作；A 重试不重复执行；重启恢复原请求；旧响应不能覆盖新状态。

### W01 · P1 · 本地 Agent 不可达被显示为未登录、无会话

位置：`pc-client/src/Windows/WindowsAgentClient.cs:82`；`Contracts/PcContracts.cs:228`；`Presentation/MainWindowViewModel.cs:555`、`:644`。

Windows 适配器把读取异常转为断开快照，其中 AccountLinked=false、会话为空；ViewModel 接收后又认为账户状态已知。启动、IPC 超时或 Agent 暂时不可达时，页面可能显示“未登录”和“暂无会话”，这些并不是当时已经确认的事实。此结论是界面状态误表达，不代表凭据真的被删除。

建议：区分“未登录 / 授权失效 / 账户暂不可确认”和“无会话 / 会话暂不可读取”。保留最后确认的身份标识并标记待确认，停用依赖实时连接的操作；仅明确认证失效进入重新授权流程。

验收：模拟一次 IPC 失败后恢复，不能误报注销或删除；真正授权失效仍需重新登录。

### Android 的进一步增强

- 设备 Agent 分组可增加一个待处理数量/小状态点，点后定位列表；无需在卡片重新铺开全部会话。
- 模型与推理强度目前已有独立能力判断和下拉，不列为缺失。后续可补模型搜索、最近选择、生成中不可修改的就地说明；“默认模型”必须区分继承电脑配置和明确选定值。
- AI 列表的“手机已打开”和“含电脑会话”、电脑原生历史、关闭手机视图、删除电脑记录应使用一套稳定文案。当前设备分组只临时浏览目录、不自动持久化全部会话的边界应保留。
- 搜索命中高亮、未加载命中定位上下文、预览读取中的进度/取消可以继续增强；当前已有搜索分页、完整消息查看、静态 HTML 预览，不能再笼统列为未实现。
- ZCode 是外部桌面远控网页，入口应一直明确该策略。返回、刷新、外部浏览器和地址失效恢复需要与原生 AI 对话区别处理，不假设网页可以共用模型/授权配置。
- 登录页可增加密码显隐、键盘下一项/提交和失败后的局部提示；不在聊天或日志输出密码。

## 不应破坏的现有行为

- 原 CLI 页面正文、Dock、控制租约和鼠标模式判断保留；目前云朵菜单按服务端策略显示功能，不能为本次交互优化重新引入 LAN/NAT 测试。
- Windows 的“停止远程访问”和安卓的“终止会话”不是同一个动作：前者走 Registry StopSession/RequestRemoteStop，后者是进程生命周期操作。需要写清楚后果，不能直接改成同一种行为。
- Windows 已有停止远程访问、会话停止、退出账户等二次确认；不应误报为没有确认。
- 模型、推理强度、授权方式继续由各 Agent 的能力决定；生成中/待审批时的配置限制不能用强制重启规避。
- 未知写入结果继续使用原 operationId；通知审批继续核对账号、主机实例、会话、控制版本和待审批 ID。
- 普通 Windows IPC 异常已有适配层转断开快照的保护，因此不把“普通断网必然永久停止轮询”列为已确认问题；真正的问题是 W01/W03 的状态表达。
- 当前静态 HTML 预览、Markdown/代码、工具汇总、公开思考/状态、历史分页和通知跳转已有实现。厂商推送的外部配置缺口见 `AI_PUSH_INTEGRATION.md`，不靠增加一个开关宣称完成。

## 推荐实施顺序

1. **数据与结果准确性**：A01/A02 草稿保护；A03 配置结果；W01 未知状态；W02 可编辑但不保存；A04 独立会话隔离。多数为客户端改动，A04 需要确认本地 pending 存储兼容与恢复。
2. **日常完整流程**：A05 返回规则；A06/A07 错误和对象确认；A08/A09 下载与更新；A10 搜索状态；W03/W04/W05 刷新、键盘和授权恢复。
3. **管理效率和一致性**：W06/W07 管理入口；A11 提醒状态；A12/A13 离线说明、本地化、紧凑度；W08/W09 更新和消息反馈。
