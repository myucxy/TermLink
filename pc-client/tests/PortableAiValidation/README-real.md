# Optional installed ZCode validation

`--real-zcode` invokes `RealZcodeValidation.RunSandboxedAsync` on macOS. The parent starts this validation executable through `/usr/bin/sandbox-exec`; `--real-isolated <directory>` is the child-only entry point. A denied, nonsecret canary must fail with an access error before ZCode is started.

The profile denies reads and writes to the existing user's `.zcode` and both `Library/Application Support/ZCode` spellings. IP networking is denied; Unix sockets remain allowed. Inherited key, token, password and provider environment variables are removed by name without reading or logging their values. Raw protocol output and stderr are never printed or retained. The sanitized `real-zcode-report.json` records method names, statuses and error codes only.

Configuration and SQLite session paths use a newly created validation directory. The raw installed runtime is allowed only `runtime/capabilities`, `session/create`, `session/subscribe`, `session/read` and `session/stop`. Runtime preferences disable memory/search enhancements; desktop headers are refused and all unknown interactions are rejected. Its requests, frames, cumulative output and process lifetime are bounded. The shared TermLink adapter is separately checked with `StartAsync` and `end`, including runtime process exit. The test sends no user turn, executes no tool and makes no model request. It does not establish desktop-account authorization or real-model functionality.

Without independent CLI model configuration, the first `session/create` may fail. That unconfigured result is explicitly recorded as `UNVERIFIED`. Only a recognized configuration/missing-model error enables a retry using a new isolated personal API provider, a visibly fake key and `http://127.0.0.1:9/v1`; IP networking remains denied and no user turn is sent. Its schema is checked against the installed bundle's provider definitions and nine personal-schema anchors before writing the test file. Unknown schema/error changes stop this fallback. Creation, subscribe/read/stop and shared adapter startup with that provider prove an installed-runtime session lifecycle, not a real-model response. The report records the normalized installed version separately from all raw vendor output.

On 2026-10-27, the installed ZCode 0.17.0 runtime passed the file/IP-denial canaries, capabilities, create/subscribe/read/stop and shared-adapter start/end/process-exit checks with an empty isolated configuration. No fallback provider was necessary; that conditional fallback branch is not established by this run. No model turn or tool was submitted. Run future checks from a Mac local build after syncing the current shared production source and project references. No application installation, signing, publishing or user account configuration is part of this validator.
