# Mac 远程文件（2026-11-04）

Mac 当前文件范围与现有手机文件协议一致：根位置／目录浏览、名称过滤、500项分页、单文件下载、目录ZIP下载、取消、网络重连与持久偏移续传，以及目录内创建CLI。
不新增手机上传、远程删除或写入接口；AI附件／文件引用／产物读取仍是独立链路，不据此宣称已完成。

- 使用既有 `file_operations_v1` / `file_operation_name_filter_v1` 和 `termlink.file-transfer.v2`，Android和iOS已有接收实现。Mac只在本地文件适配库可用时上报能力。
- 文件任务独立于终端心跳，最多4项并行。每2秒重新验证请求手机MANAGE、密钥epoch、服务端操作租约，撤权／取消／停用会停止发送。
- 文件内容使用已有X25519与ChaCha20-Poly1305协议端到端加密；服务器不解密。接收端持久连续偏移决定重连起点，最终由SHA-256和CompleteAck确认后才完成服务端任务。
- 文件和ZIP先生成不可变快照；同操作ID重试使用同字节和摘要，即使原文件已经变化。临时目录仅当前用户可访问，载荷权限0600，重启可核验并继续读取同一快照，旧孤立缓存26小时后清理。缓存不是加密存储，完成／取消／撤权后清理。
- macOS逐组件openat/O_NOFOLLOW读取，用已打开目录句柄递归；不会跟随用户符号链接或读取FIFO／设备。手机列表仅返回普通文件和目录，ZIP跳过链接和特殊文件。/tmp、/var、/etc固定系统别名映射至/private路径。
- 单传输最大5GiB，目录最大100000项／64层；归档同时限制压缩前和写出字节。源文件增长超限、无权限、无效文件名会失败并返回固定错误码。
- macOS“文件与文件夹”／完全磁盘访问由系统决定，TermLink不绕过授权。目录不可读时显示权限错误，不能因为本机有Shell就假定所有目录可读。

已有Android版本把CLI按钮误绑文件能力；本次源码修复独立CLI门控，并为Mac提供直接输入绝对目录的入口，避免依赖AI目录能力。文件按钮仍要求真实文件能力。
本机没有Android JDK／SDK／Gradle，Android新增JUnit未执行、未生成或安装APK。新的Mac文件能力在现有手机读取最新能力清单后，可启用已有文件入口；具体手机版本仍需实机验收。

本机验证使用真实native文件访问、实际生产签名HTTP／加密WebSocket：Unicode、筛选、分页、空文件、ZIP、缓存重载、源变更稳定、篡改、符号链接／循环／逃逸、取消、大小限制、中途断线续传、撤权、完整摘要与服务器完成确认。
这些受控联测不能替代真实手机／线上服务验收。服务端路由权限的配套收紧未部署，本轮不执行部署。
